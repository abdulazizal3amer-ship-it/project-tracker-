# وثيقة متطلبات الأعمال – نظام إدارة المشاريع والمهام

Oct 14, 2026 · @abdulaziz

## 1. المقدمة والنطاق

المطلوب تطبيق ويب خفيف لإدارة المشاريع والمهام لفريق من نحو 10 أشخاص (منهم 5 مدراء مشاريع)، دون أي خادم تديره الجهة: الواجهة على GitHub Pages، والبيانات وحسابات المستخدمين في قاعدة بيانات Supabase المُدارة (الخطة المجانية).

المشكلة الحالية: المهام موزعة بين الواتساب والإيميل وملفات Excel، فلا يعرف أحد بدقة من يعمل على ماذا، وما المتأخر، وما نسبة إنجاز كل مشروع.

الأهداف:

1.  مكان واحد لكل المشاريع والمهام ومسؤوليها ومواعيدها.

2.  رؤية فورية لحالة كل مشروع ونسبة إنجازه والمهام المتأخرة.

3.  سهولة الاستخدام: يتعلمه أي عضو في الفريق خلال أقل من 30 دقيقة دون تدريب.

4.  تكلفة تشغيل صفرية: لا خوادم تحتاج صيانة؛ الكود على GitHub والبيانات في Supabase المجانية.

داخل النطاق: المستخدمون والأدوار، المشاريع، المهام (مع إسنادها لعضو واحد أو مجموعة أعضاء) والمهام الفرعية، لوحة كانبان، التعليقات والمرفقات، الإشعارات، لوحة متابعة وتقارير بسيطة، واجهة عربية وإنجليزية.

خارج النطاق (عمداً للحفاظ على البساطة): مخططات جانت المتقدمة، إدارة الموارد والميزانيات، تتبع الوقت والفوترة، تطبيق جوال أصلي (يكفي تصميم متجاوب)، التكامل مع أنظمة ERP، الصلاحيات المعقدة متعددة المستويات، أي خادم خاص يحتاج تثبيتاً أو صيانة.

## 2. الأدوار والصلاحيات

ثلاثة أدوار فقط تكفي لفريق من 10 أشخاص؛ أي دور إضافي يزيد التعقيد دون فائدة حقيقية.

| الدور                        | العدد المتوقع                       | ما يستطيع فعله                                                                                           |
|-----------------------------------------------------|------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| مدير النظام (Admin)          | 1 (يمكن أن يكون أحد مدراء المشاريع) | كل الصلاحيات + إنشاء حسابات المستخدمين وتعطيلها وتغيير أدوارهم وإعدادات النظام                           |
| مدير مشروع (Project Manager) | 5                                                          | إنشاء المشاريع، إضافة الأعضاء، إنشاء المهام وإسنادها لعضو أو أكثر وحذفها، رؤية التقارير                  |
| عضو فريق (Member)            | نحو 5                               | رؤية مشاريعه، تحديث حالة المهام المسندة إليه (منفرداً أو ضمن مجموعة)، التعليقات والمرفقات، المهام الفرعية |

الحسابات محفوظة في جدول المستخدمين بقاعدة البيانات: ينشئ المدير الحساب بالاسم والبريد والدور وكلمة مرور مؤقتة، ويغيّرها المستخدم عند أول دخول. لا يحتاج أحد حساب GitHub إلا المطور.

أصحاب المصلحة: الإدارة (مستفيد من التقارير)، مديرو المشاريع (المستخدم الرئيسي)، أعضاء الفريق، والمطور/المسؤول التقني (التثبيت والصيانة).

## 4. قصص المستخدم ومعايير القبول

**US-01 — إنشاء مشروع (FR-05)** بصفتي مدير مشروع، أريد إنشاء مشروع وإضافة أعضائه، حتى يرى الفريق المشروع ويبدأ العمل عليه.

- ☐ لا يُحفظ المشروع دون اسم وتاريخ نهاية.

- ☐ تاريخ النهاية لا يسبق تاريخ البداية.

- ☐ يظهر المشروع فوراً لكل الأعضاء المضافين فقط.

**US-02 — إسناد مهمة لعضو أو مجموعة (FR-08، FR-09، FR-22)** بصفتي مدير مشروع، أريد إسناد المهمة لعضو واحد أو لعدة أعضاء معاً بتاريخ استحقاق، حتى يعرف كل منهم ما المطلوب ومتى.

- ☐ يمكن اختيار أكثر من عضو من قائمة أعضاء المشروع، أو اختيار "كل أعضاء المشروع"، أو مجموعة محفوظة.

- ☐ لا يمكن الإسناد إلا لأعضاء المشروع، ويجب اختيار عضو واحد على الأقل.

- ☐ يصل إشعار فوري داخل التطبيق لكل المسندين، وتظهر المهمة في صفحة "مهامي" لدى كل منهم.

- ☐ إن غيّر أي عضو حالة المهمة الجماعية، تتغير للجميع ويُسجَّل اسمه في السجل.

**US-03 — تحديث الحالة بالسحب (FR-11، FR-15)** بصفتي عضواً في الفريق، أريد سحب بطاقة مهمتي إلى العمود التالي، حتى أحدّث حالتها بخطوة واحدة.

- ☐ تتغير الحالة وتُحفظ دون إعادة تحميل الصفحة.

- ☐ يُسجل التغيير في سجل النشاط باسمي ووقته.

- ☐ لا أستطيع سحب مهمة لست ضمن المسندين إليهم (إلا إن كنت مدير المشروع).

- ☐ عند النقل إلى "مكتملة" تُحدَّث نسبة إنجاز المشروع تلقائياً.

**US-04 — متابعة المتأخر (FR-24، FR-25)** بصفتي مدير مشروع، أريد رؤية المهام المتأخرة فور دخولي، حتى أتدخل مبكراً.

- ☐ المهمة المتأخرة = تاريخ استحقاقها مضى وحالتها ليست "مكتملة".

- ☐ تظهر في اللوحة الرئيسية مرتبة من الأقدم تأخراً، مع اسم المسؤول وعدد أيام التأخر.

**US-05 — التعليق والإشارة (FR-19)** بصفتي عضواً، أريد كتابة تعليق والإشارة لزميل بـ @، حتى أطلب منه شيئاً في سياق المهمة.

- ☐ كتابة @ تعرض قائمة بأعضاء المشروع.

- ☐ يظهر للزميل المُشار إليه إشعار فوري برابط مباشر للمهمة.

**US-06 — تقرير المشروع (FR-26)** بصفتي مديراً، أريد تصدير تقرير المشروع، حتى أشاركه في الاجتماع الأسبوعي.

- ☐ يتضمن التقرير: نسبة الإنجاز، المهام حسب الحالة، المهام حسب العضو، قائمة المتأخر.

- ☐ يُصدَّر بصيغة CSV وPDF ويدعم العربية بشكل صحيح.

## 5. نموذج البيانات المبسط

قاعدة بيانات PostgreSQL على Supabase من 12 جدولاً، أهمها جدول المستخدمين users. الإسناد المتعدد يتم عبر جدول ربط task_assignees بين المهام والمستخدمين.

| الجدول | الحقول الأساسية                                                                                                | العلاقات                     |
|-------------------------------|---------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------|
| users                         | id، full_name، email (فريد)، role (admin/pm/member)، language، avatar_url، is_active، must_change_password، last_login_at، created_at | أساس كل الجداول              |
| groups                        | id، name، created_by                                                                                                                  | مجموعة محفوظة للإسناد السريع |
| group_members                 | group_id، user_id                                                                                                                     | يربط المستخدمين بالمجموعات   |
| projects                      | id، name، description، start_date، end_date، status، manager_id، created_at                                                           | مديره من users               |
| project_members               | project_id، user_id                                                                                                                   | يربط المستخدمين بالمشاريع    |
| tasks                         | id، project_id، title، description، status، priority، due_date، created_by، completed_at، completed_by                                | تتبع مشروعاً                  |
| task_assignees                | task_id، user_id، assigned_by، assigned_at                                                                                            | الإسناد لعضو أو أكثر         |
| subtasks                      | id، task_id، title، assignee_id (اختياري)، is_done                                                                                    | تتبع مهمة                    |
| comments                      | id، task_id، user_id، body، created_at                                                                                                | تتبع مهمة                    |
| attachments                   | id، task_id، file_name، storage_path، size، uploaded_by                                                                               | الملف في Supabase Storage    |
| activity_log                  | id، task_id، user_id، action، old_value، new_value، created_at                                                                        | سجل تغييرات المهمة           |
| notifications                 | id، user_id، type، task_id، message، is_read، created_at                                                                              | موجّه لمستخدم                 |

حماية جدول المستخدمين: كلمات المرور لا تُخزَّن نصاً أبداً؛ تتولى Supabase Auth تشفيرها (bcrypt) وجدول users يرتبط بها بنفس id. لا يستطيع أحد تعديل الدور أو التفعيل إلا مدير النظام، عبر سياسات أمان على مستوى الصفوف (RLS).

النسخ الاحتياطي: الخطة المجانية لا تشمل نسخاً يومية، لذا يُصدِّر GitHub Actions مجدول نسخة أسبوعية من قاعدة البيانات إلى مستودع GitHub خاص.

قواعد عمل: حذف المشروع = أرشفة لا حذف فعلي؛ تعطيل المستخدم لا يحذف مهامه بل تبقى ظاهرة باسمه مع علامة "معطّل"؛ عند اكتمال المهمة يُسجّل completed_at وcompleted_by تلقائياً؛ إزالة عضو من المشروع تزيله من مسؤولي مهامه المفتوحة مع تنبيه مدير المشروع.

## 7. التقنية المقترحة وهيكل مستودع GitHub

التوصية: تطبيق صفحة واحدة (SPA) منشور على GitHub Pages، يتصل مباشرة بقاعدة بيانات Supabase المُدارة للحسابات والبيانات والملفات. لا خادم تثبّته الجهة أو تصونه، والتكلفة صفر على الخطة المجانية.

| الطبقة            | الخيار المقترح                         | سبب الاختيار                                        |
|------------------------------------------|---------------------------------------------------------------|----------------------------------------------------------------------------|
| الواجهة           | React + Vite + Tailwind                                       | يُبنى ملفات ثابتة تصلح لـ GitHub Pages، ودعم RTL سهل |
| الاستضافة         | GitHub Pages                                                  | مجانية وHTTPS تلقائي                                |
| قاعدة البيانات    | Supabase (PostgreSQL)                                         | جدول مستخدمين وعلاقات حقيقية، وخطة مجانية           |
| الحسابات والدخول  | Supabase Auth (بريد وكلمة مرور)                               | تشفير كلمات المرور واستعادتها جاهزان                |
| الصلاحيات         | Row Level Security في PostgreSQL                              | الحماية داخل القاعدة لا في المتصفح                  |
| الإشعارات الفورية | Supabase Realtime                                             | تحديث فوري دون خادم                                 |
| الملفات           | Supabase Storage                                              | المرفقات والصور الشخصية                             |
| التصدير           | jsPDF و Papa Parse في المتصفح                                 | تقارير PDF وCSV                                     |
| النشر             | GitHub Actions يبني التطبيق وينشره تلقائياً عند كل دمج في main | لا خطوات يدوية                                      |

إنشاء الحسابات من شاشة المدير يتم عبر Supabase Edge Function صغيرة تحمل مفتاح الخدمة، لأن هذا المفتاح لا يجوز وضعه في الواجهة.

مستودع GitHub واحد يحوي الكود وملفات إنشاء قاعدة البيانات؛ يمكن أن يكون عاماً لأنه لا يحوي أي بيانات أو أسرار.

- البيانات والحسابات تعيش في Supabase لا في GitHub.

- عنوان مشروع Supabase والمفتاح العام يُضبطان كـ Secrets في GitHub Actions ويُحقنان عند البناء.
